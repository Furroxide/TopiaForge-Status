# Status service review, 2026-11-04

The final source changes received a thorough independent review across the status service and its control-plane integration. No actionable findings remain in the reviewed source. Live commissioning is a separate gate.

## Corrections and evidence

- **Incident durability:** observations, monitoring start, incident transitions and optional activity commit in one D1 batch. An injected interrupted write fails on the previous implementation and passes after the correction. Replaying a delivery cannot permanently omit its incident.
- **Telemetry isolation:** stale or malformed activity no longer discards otherwise valid uptime checks. Expired control-plane snapshots stop being released even if collection and cleanup have stopped.
- **Privacy delay:** the fifteen-minute delay starts after the final shard response. A deferred collection reproduced premature publication before the fix; the corrected test confirms the full delay.
- **History correctness:** details and archives are read in one database snapshot, avoiding a duplicate-count race during retention. The 90-day view uses UTC calendar-day bins; latency remains bounded to thirty days even when cleanup is delayed. Complete archived history stays visibly covered, and partial coverage stays distinct.
- **Incident visibility:** unresolved incidents are retained independently of the bounded list of resolved incidents. An old open incident remains visible after hundreds of newer recoveries.
- **HTTP headers:** asset responses carry CSP, referrer policy and nosniff through the static asset header configuration. Actual local HTTP responses were checked; direct calls to the Worker alone did not detect the original routing bypass.
- **Signaling:** malformed frames fail a probe without crashing the monitor. A connection must forward a valid offer and answer in both directions to pass; welcome messages alone are insufficient.
- **TURN authentication:** signed requests require valid response MESSAGE-INTEGRITY, compared in constant time. Attributes after integrity cannot replace authenticated relay addresses. Unsigned and modified successes are rejected; published RFC 5769 response data is accepted. The independent review separately verified the published response and tamper rejection.
- **TURN cleanup under excess traffic:** the diagnostic buffer limit applies only to application data. At capacity, authenticated permission, channel and release acknowledgments still resolve. A mixed-frame regression failed before the fix and passed in both transport copies; independent review reproduced the defect and verified the correction.
- **Diagnostics and accessibility:** live checks no longer emit token prefixes or relay endpoint values. Background refresh preserves table expansion, reading position and keyboard focus. Large activity tables display a bounded recent portion while the chart covers the selected window.
- **Measurement transparency:** maintenance retains an explicit underlying measurement state and cannot hide the separate unavailable-measurements warning. Per-service monitoring start times also appear visually and in the accessible table, so a newly started measurement period cannot imply complete older history. The stale/blocked maintenance regression failed before the fix and passed afterward, including independent verification. Desktop/mobile rendering and table keyboard access passed with no overflow or browser errors.

## Verification boundary

The final local checks passed: 247 existing control-plane tests, eleven enabled-activity tests, six transport tests in the actual control-plane package, and 34 status-service checks. Type checking, Worker bundles and real local HTTP routes also passed. Runtime tests use loopback fixtures; no native game acceptance or live service uptime is inferred from them.

The legacy MD5 CodeQL finding has been independently reviewed in its exact protocol context; see [TURN security review](turn-security-review.md). This supports a targeted false-positive disposition, without disabling CodeQL or accepting other uses of weak cryptography. Deployment credentials, protected deployment approval, DNS/HTTPS verification and real unattended observations remain commissioning requirements.

The first protected status deployment provisioned the custom domain successfully. Its immediate smoke check reproduced a DNS propagation race. Public DNS, HTTPS, assets, security headers, all history ranges, incident data and anonymous-write rejection then passed independent HTTP verification. The deployment check now retries transient transport failures within fixed limits and preserves HTTP/schema/authentication failures. That correction received an independent diff review. The committed commissioning note describes this real rollout without adding synthetic uptime history.
